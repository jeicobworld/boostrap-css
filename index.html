Estructura y sintaxis

Imagina que le das órdenes a un robot. Primero le dices a quién le hablas: h1 significa "los títulos grandes". Luego abres una caja con llaves { }. Dentro le dices qué cambiar (color) y cómo (blue, azul), con dos puntos en medio.

Cada orden termina con punto y coma ;. Si te olvidas de uno, el robot se confunde y puede ignorar tu orden.

  • Una regla (rule set) = selector + bloque de declaraciones. Cada declaración es propiedad: valor;.
  • Selectores básicos: tipo (h1), clase (.card), id (#menu), atributo ([type="text"]) y universal (*).
  • Combinadores: descendiente (espacio), hijo directo (>), hermano adyacente (+) y hermano general (~). La coma agrupa selectores.
  • Si una declaración es inválida, el navegador la descarta y sigue con la siguiente ;. El resto del bloque sí se aplica.
  • Tipos de valor: longitudes (px, rem, %), colores (#hex, rgb(), hsl()) y funciones (calc(), var()).

Tipos de incorporación

Piensa que el HTML es un muñeco y el CSS es su ropa. Hay tres formas de vestirlo:

Externo: la ropa está en un armario aparte (el archivo styles.css) y el muñeco la toma con <link>. Sirve para vestir a muchos muñecos (páginas) con la misma ropa.

Interno: la ropa va en una bolsita pegada al muñeco (<style>). Solo sirve para esa página.

En línea: le pegas la ropa directo a una sola parte (style="color:red"). Es rápido, pero queda desordenado.

  • Externo: <link rel="stylesheet" href="styles.css"> en el <head>. Se cachea entre páginas, pero bloquea el renderizado hasta que se descarga y se construye el CSSOM.
  • Interno: <style> en el <head>. No hace petición HTTP extra, pero no se reutiliza entre páginas.
  • En línea: atributo style="". Especificidad más alta (1000) y no admite pseudo-clases, pseudo-elementos ni media queries.
  • Evita @import dentro del CSS: serializa las descargas y retrasa el render.
  • Con el mismo peso gana la regla declarada más abajo, por eso el CSS propio va después del de Bootstrap.

Identación, herencia y comentarios

Identación: dejar espacios al inicio de cada línea, como el margen de un cuaderno. No cambia lo que hace el código, solo lo hace fácil de leer.

Herencia: es como un hijo que se parece a sus papás. Si le pones color gris a body (el papá), todos los párrafos (los hijos) lo copian solos. Pero no todo se hereda: el borde no pasa de padres a hijos.

Comentarios: son notas secretas entre /* y */. El navegador no las lee, solo las personas.

  • Se heredan por defecto: color, font-family, font-size, line-height, text-align, visibility, cursor, list-style.
  • No se heredan: margin, padding, border, background, width, display.
  • Palabras clave para controlarlo: inherit (copia al padre), initial (valor de la especificación), unset y revert.
  • Los comentarios solo existen como /* */. No hay // en CSS y no se pueden anidar.
  • Convención: 2 o 4 espacios de sangría y una declaración por línea. Al publicar se suele minificar.

Niveles de especificidad

Si una orden dice "rojo" y otra dice "azul" para lo mismo, el navegador tiene que elegir. Gana la más fuerte, y la fuerza se mide en puntos:

La etiqueta p vale 1, la clase .texto vale 10, el id #titulo vale 100 y lo escrito directo con style="" vale 1000. Gana quien tenga más puntos. Si empatan, gana la que está escrita más abajo.

!important es como gritar: casi siempre gana, pero si todos gritan se arma un caos.

  • La especificidad es un vector (a, b, c): a = ids, b = clases, atributos y pseudo-clases, c = tipos y pseudo-elementos.
  • Se compara de izquierda a derecha: 11 clases no superan a 1 id. Lo de 1, 10 y 100 es solo un atajo para entenderlo.
  • Ejemplo: nav ul li.activo a:hover = (0, 2, 4).
  • *, los combinadores y :where() aportan 0. :is() y :not() toman el argumento más específico.
  • Orden de resolución en la cascada: origen e !important → @layer → especificidad → orden de aparición.
  • Buena práctica: baja especificidad (clases) y evita ids y !important en los estilos.

Flexbox, Grid y breakpoints

Flexbox: es una fila de niños en un pasillo. Con display: flex todos se ponen uno al lado del otro, y tú decides si van juntos, separados o centrados.

Grid: es un cuaderno cuadriculado. Tú dices cuántas filas y columnas hay, y pones cada cosa en su casilla.

Breakpoints: son las medidas donde la pantalla "cambia de talla" (celular, tablet, computador) y la página cambia de forma. En Bootstrap son 576, 768, 992, 1200 y 1400 px.

  • Flexbox es unidimensional: eje principal (flex-direction) y eje cruzado. justify-content alinea en el principal y align-items en el cruzado.
  • Cada item usa flex: grow shrink basis. También flex-wrap y gap.
  • Grid es bidimensional: grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)), grid-template-areas, unidad fr, gap.
  • Regla práctica: flex cuando el contenido manda en el tamaño (barras de menú). Grid cuando el layout manda (rejillas de tarjetas).
  • Breakpoints de Bootstrap 5 (min-width, mobile-first): sm 576, md 768, lg 992, xl 1200, xxl 1400.

Media queries

Es una regla de "si… entonces". Por ejemplo: SI la pantalla mide 768 píxeles o más, ENTONCES pon dos columnas.

Un celular es angosto y un computador es ancho. Se empieza diseñando para el celular (una columna) y se agregan @media que dicen "si la pantalla crece, cámbialo así".

  • Sintaxis: @media (min-width: 768px) { ... }. Se aplica solo si la condición es verdadera.
  • Tipos: screen, print. Características: width, height, orientation, prefers-color-scheme, prefers-reduced-motion, hover, resolution.
  • Operadores: and, not, only. La coma funciona como "o". Sintaxis moderna de rangos: @media (width >= 768px).
  • Mobile-first usa min-width (menos CSS por sobrescribir). Desktop-first usa max-width. Bootstrap usa 767.98px para evitar solapamientos con zoom decimal.
  • Requiere <meta name="viewport" content="width=device-width, initial-scale=1">. Para adaptar un componente y no la página entera existen las @container queries.

Pseudo-elementos y pseudo-clases

Pseudo-clase (un :) es el "estado de ánimo" de un elemento. Un botón está tranquilo, pero cuando le pasas el mouse encima se emociona (:hover). Cuando lo aprietas está :active. Y :first-child es "el primero de la fila".

Pseudo-elemento (dos ::) es un pedacito invisible que CSS puede inventar. ::after pone un adorno después del texto, como una estrella ★, sin escribirla en el HTML.

  • Pseudo-clases (:): dinámicas (:hover, :focus, :focus-visible, :active), estructurales (:nth-child(2n+1), :first-child, :last-of-type), de formulario (:checked, :disabled, :invalid) y lógicas (:not(), :is(), :where(), :has()).
  • Pseudo-elementos (::): ::before y ::after solo se generan si defines content (aunque sea ""). Son inline por defecto.
  • Otros: ::placeholder, ::selection, ::marker, ::first-letter, ::first-line.
  • El contenido de ::before y ::after no se puede seleccionar ni está en el DOM: úsalo para decoración, no para información importante.
  • CSS3 separó la sintaxis: : para clases y :: para elementos. Los navegadores aceptan :before por compatibilidad.

Z-index

Imagina hojas de papel apiladas sobre una mesa. La hoja de arriba tapa a la de abajo. z-index es el número que dice cuál va arriba: el 3 le gana al 1.

Ojo: solo funciona si el elemento está "suelto" con position (relative, absolute, fixed o sticky). Si la hoja está pegada a la mesa, el número no hace nada.

  • Aplica a elementos con position distinto de static y a los items de un contenedor flex o grid.
  • Cada contexto de apilamiento (stacking context) es una "caja cerrada": un hijo con z-index: 9999 dentro de un padre con z-index: 1 sigue debajo de un hermano del padre con z-index: 2.
  • Crean contexto: z-index distinto de auto en elementos posicionados, opacity < 1, transform, filter, position: fixed o sticky, isolation: isolate y will-change.
  • Orden de pintado dentro de un contexto: fondo → z-index negativos → bloques → flotantes → inline → z-index: 0/auto → positivos.
  • Buena práctica: una escala con variables (--z-nav: 100, --z-modal: 1000) y no usar valores como 9999. Bootstrap usa 1030 en la navbar fija y 1055 en los modales.
